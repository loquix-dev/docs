`<loquix-search-dialog>` is the command-palette form of smart search. An inline trigger sits on the page; activating it opens a native modal holding a second input, the AI answer, the source strip, the results, and the shortcut footer.

## Usage

```js
import '@loquix/core/define/define-search-dialog';
```

```html
<loquix-search-dialog placeholder="Search the docs…" kbd="⌘K"></loquix-search-dialog>
```

Wire your own shortcut to open it, then fill the data in the ask handler.

```js
const dialog = document.querySelector('loquix-search-dialog');

document.addEventListener('keydown', (event) => {
  if (event.key === 'k' && (event.metaKey || event.ctrlKey)) {
    event.preventDefault();
    dialog.open = true;
  }
});

dialog.addEventListener('loquix-search-ask', async (event) => {
  dialog.state = 'searching';
  dialog.answerState = 'generating';

  const response = await ask(event.detail.query);

  dialog.answerContent = response.answer;
  dialog.answerSources = response.citations;
  dialog.results = response.hits;
  dialog.sources = response.backends;
  dialog.state = 'idle';
  dialog.answerState = 'complete';
});
```

## Dialog or panel

The data API is identical to [Search Panel](/docs/components/search-panel/); the difference is presentation. The dialog renders a native `<dialog>` as a modal, which brings focus trapping and the platform's own Escape handling. Reach for it when search is a global action invoked by a shortcut. Prefer the panel when search belongs to one region of a page and the surrounding content should stay readable.

## Data properties

Set as properties, exactly as on the panel.

| Property | Type | Description |
| --- | --- | --- |
| `sources` | `SearchSource[]` | Back ends for the progress strip and filter chips. See [the search source object](/docs/components/search-sources/#the-search-source-object). |
| `results` | `SearchResult[]` | Result rows. See [the search result object](/docs/components/search-result/#the-search-result-object). |
| `answerSources` | `Source[]` | Sources cited by the answer. See [the source object](/docs/components/citation-popover/#the-source-object). |
| `shortcuts` | `SearchShortcut[]` | Footer shortcuts. See [the shortcut object](/docs/components/search-footer/#the-shortcut-object). |

<Aside type="caution" title="Two kinds of source, deliberately">
	`sources` describes the back ends a query fanned out to. `answerSources` describes the documents the answer cites. They are different shapes and are not interchangeable.
</Aside>

## Events

| Event | Detail | Description |
| --- | --- | --- |
| `loquix-search-dialog-open` | `{ value }` | Fired when the modal opens. |
| `loquix-search-dialog-close` | `{ value }` | Fired when the modal closes. |

The embedded input's `loquix-change`, `loquix-search-submit`, and `loquix-search-ask` events bubble out of the dialog.

<Aside type="caution" title="Closing in code is silent">
	Setting `open = true` fires the open event, but setting `open = false` closes the modal without firing the close event. `loquix-search-dialog-close` reports user-driven closes — the close button, the backdrop, or Escape. If you also close it from code, do the bookkeeping there rather than relying on the event. [Search Panel](/docs/components/search-panel/) fires both directions either way.
</Aside>
