`<loquix-search-panel>` is a whole smart search surface in one element. It renders an inline input that expands downward into an anchored overlay holding the AI answer, the source strip, the results, and the shortcut footer — no modal, and the page stays visible behind it.

## Usage

```js
import '@loquix/core/define/define-search-panel';
```

```html
<loquix-search-panel placeholder="Search the docs…" kbd="⌘K"></loquix-search-panel>
```

The panel owns its open state and the layout; you supply the data and react to the submit events, which come from the embedded [Search Input](/docs/components/search-input/).

```js
const panel = document.querySelector('loquix-search-panel');

panel.addEventListener('loquix-search-ask', async (event) => {
  panel.state = 'searching';
  panel.answerState = 'generating';

  const response = await ask(event.detail.query);

  panel.answerContent = response.answer;
  panel.answerSources = response.citations;
  panel.results = response.hits;
  panel.sources = response.backends;
  panel.runningTotal = response.hits.length;
  panel.state = 'idle';
  panel.answerState = 'complete';
});
```

## Panel or dialog

[Search Dialog](/docs/components/search-dialog/) has the same data API but opens a modal `<dialog>` over the page. Use the panel when search sits inside a page layout and the surrounding content should stay visible; use the dialog for a command-palette experience reached by a shortcut from anywhere.

The `detached` variant floats the overlay below the input; `integrated` draws one continuous surface around the input and the panel.

## Data properties

Every collection is an array set as a property.

| Property | Type | Description |
| --- | --- | --- |
| `sources` | `SearchSource[]` | Back ends for the progress strip and filter chips. See [the search source object](/docs/components/search-sources/#the-search-source-object). |
| `results` | `SearchResult[]` | Result rows. See [the search result object](/docs/components/search-result/#the-search-result-object). |
| `answerSources` | `Source[]` | Sources cited by the AI answer. See [the source object](/docs/components/citation-popover/#the-source-object). |
| `shortcuts` | `SearchShortcut[]` | Footer shortcuts. See [the shortcut object](/docs/components/search-footer/#the-shortcut-object). |

<Aside type="caution" title="Two kinds of source, deliberately">
	`sources` describes the back ends a query fanned out to. `answerSources` describes the documents the answer cites. They are different shapes and are not interchangeable.
</Aside>

## Events

| Event | Detail | Description |
| --- | --- | --- |
| `loquix-search-panel-open` | `{ value }` | Fired when the panel expands. |
| `loquix-search-panel-close` | `{ value }` | Fired when the panel collapses. |

The embedded input's `loquix-change`, `loquix-search-submit`, and `loquix-search-ask` events bubble out of the panel, so you listen for them here.

## Slots

| Slot | Purpose |
| --- | --- |
| `prefix` | Prefix content for the inline input. |
| `suggestions` | Pre-search suggestions, commonly [Suggestion Chips](/docs/components/suggestion-chips/). |
| `answer` | Custom answer content replacing the built-in answer block. |
| `footer-actions` | Trailing footer actions. |
